# 8面のボス造形・機構の改修

更新日：2026-11-03

依頼は「各面ごとに特徴のある機構と、リアルでカッコいいボス」。既存の道中、機体、フォース、波動砲、音楽、撃破の爆発を保持し、ボス8体を専用モデル・固有の状態遷移・部位破壊で作り直した。

## 遊び方

公開先は既存の [R-TYPE // REQUIEM](https://yawakihara.github.io/R-TYPE/)。通常の8面キャンペーンに組み込み済み。「FLIGHT TRAINING」→「BOSS / ボス直行」では、装備・難易度・フリーフライトを選んで直接対戦できる。ミス後も同じボスから再開し、撃破後は次面のボスへ進む。

発光する小部位と耐久バーを狙って部位を破壊する。上部HUDに機構の状態、残存部位数、攻略ヒントを表示する。HPが45%未満になると第2段階へ移り、攻撃間隔や開放時間が変わる。レーザー・圧砕柱には1.4〜1.6秒の予告があり、照準確定後の線は自機を追尾しない。

## 各面の機構

1. **DOORKEEPER**：装甲防御 → 連装砲斉射 → 排熱。排熱中に核が開く。2基の砲塔を壊すと砲撃が減り、排熱の隙が1.5秒延びる。
2. **GORGON**：捕食準備 → 顎の予告 → 自機側へ急突進 → 消化。消化中に口内が弱点。孵化嚢の残存数が幼体の出現数になる。顎は予告・突進・露出で開き方が変わる。
3. **COLOSSUS CORE**：迎撃 → 主砲照準 → 放射 → 冷却。砲身角度とビーム線を合わせ、長砲身の先から流れる放射光を描く。冷却装置2基の両方を壊して初めて冷却中の炉心が開く。
4. **JUDGEMENT**：座標検索 → 圧砕予告 → 縦の焼却柱 → アーム収納。収納時に中央核が露出。上下のサーボを両方壊すと圧砕柱は2本から1本へ減る。
5. **OUROBOROS**：骨環収束 → 突進予告 → 骨竜突進 → 骨環展開。骨弾の扇と大顎で攻撃する。骨棘を両方壊すと展開時間が1.5秒延びる。旧版の汎用モデル・球状の尾の使い回しは、専用の骨環・頸椎・顎の造形へ置き換えた。
6. **MNEMOSYNE**：3つの神経節が核を守る。全破壊で弾幕を消し、過負荷中に核を開く。閉鎖・再生後に神経節が戻る。傘、触手、前面の3節を独立して動かし、破壊した節を消す。
7. **THE ARBITER**：光翼回転 → 格子予告 → レーザー格子 → 停止。格子の間に避けられる隙間を残し、停止時に核を開く。2つの制御器の全破壊で格子は4本から2本へ減る。第2段階は射線が傾く。
8. **ORIGIN**：心拍 → 収縮予告 → 心拍衝撃 → 拡張。核に対する弾は無効。拡張中にフォースを直接接触させると吸着し、拡張中だけ損傷する。動脈弁を両方破壊すると拡張時間が延びる。装備なしで到達しても、赤クリスタルを落とす補給機からフォースを入手できる。

## 制作物と実装

- `art/requiem-bosses.blend`：8体を並べた編集用Blenderデータ。
- `tools/make_bosses.py`：Blender 5.2用の再生成スクリプト。既存の基本モデルは変更しない。
- `public/models/bosses.glb`：8ルート、関節・独立破壊部位、21材質、12枚の埋め込み画像。14,220,056 bytes。色・法線マップを使用し、外部画像への実行時通信はない。
- `src/bosses.js`：8体の機構、部位・核の座標、攻撃予告、射撃・接触判定。ビームの判定は描画と同じ線分を使用。モデル本体の接触判定は輪郭に合わせた楕円・線分等の簡略判定。
- `src/boss-visuals.js`：各Blender関節、破壊した部位の欠損、破断面、耐久バー、核、シールド、放射光。GPU資源を使い回し、個体終了時に個体専用資源を解放する。
- ボス状態に合わせて警告、過負荷、シールド崩壊、心拍の合成音を追加。既存の11曲と波動砲の音響は保持。

## 実施した検証

- Blenderのバックグラウンド生成は終了コード0。編集用一覧レンダリングを目視確認。
- GLBをBlenderとは独立して読み取り、全8ルートの原点、名前一意、関節、部位の座標、埋め込み画像、法線素材を検証。
- `npm test`：39件合格。部位破壊条件、再生、装甲・露出時のダメージ、照準固定、予告中の無害性、発射後の衝突、格子の回避間隔、第2段階、最終核のフォース限定、装備なしの補給、再出撃を含む。
- 無敵を指定した検証用パイロットが、通常の入力・射撃・部位破壊・フォース操作を使用し、道中込みの8面キャンペーンとボス直行の8連戦を完走。HPや撃破判定を直接書き換えてクリアしていない。
- 個体の長時間更新で描画資源が増えないこと、個体終了時に共有GLB形状・素材を解放しないことを検証。
- `npm run build`：静的配布物を生成。既存の波動砲・命中・敵撃破のテストも合格。
- 実ブラウザーで8体すべての核露出フレームと、戦艦主砲・圧砕柱・レーザー格子を確認。検証タブの警告・エラーログは0件。[生データ](boss-browser-check.json) と `screenshots/boss-stage-01.png`〜`08.png`、`boss-attack-3.png`・`4.png`・`7.png` に保存。
- 配布ビルドで「FLIGHT TRAINING」→「BOSS」→装備選択→出撃を実操作。RTX 5070 / IAB / HIGH / 1280×720の回転防衛機戦で60FPSを確認し、波動砲の発射・ボスの回転・HUDを目視確認。

自動パイロットの完走は進行不能の検証であり、人が全難易度を無被弾でクリアしたという意味ではない。全機種でのフレームレートと、全難易度の人による攻略バランスは未確認。
